# 测试样本集与基线

8 份样本，覆盖规则库 43 条规则中的 39 条。所有机构名、产品名、人员姓名均为虚构。

样本分两类用途：**违规样本**验证「能不能检出」，**合规样本**验证「会不会乱报」。后者更重要——误报率决定这个工具能不能真正被合规人员使用。

## 二、各样本的设计意图

### 1. `sample-public-fund-violating.md` · 公募违规版

```bash
--product public_fund --audience public --media online --institution fund_manager
```

最全面的违规样本，覆盖预期收益宣传、饥饿营销、绝对化用语、推荐性文字、业绩展示不规范、必备声明缺失等。

**重点观察**：报告是否为每一项都附上了法条原文；未生效的 2 项（「低风险」「低门槛」，依据 2026-09-30 施行的《金融产品网络营销管理办法》）是否被单独分节列出，而非与现行违规混在一起。

### 2. `sample-public-fund-compliant.md` · 公募合规版

```bash
--product public_fund --audience public --media online --institution fund_manager
```

一份完全合规的产品介绍，**期望 violation 为 0**。

这份样本在开发期抓出过三个严重误报：证监会法定注册声明中的「没有风险」、《运作管理办法》风险收益特征标准句式中的「预期收益」、法定允许的「业绩比较基准收益率」。这类误报比漏报危险——合规人员照着改，材料会从合规变成缺失法定要素。

**重点观察**：报告是否报出了 violation。只要有一条，就是误报。

### 3. `sample-public-fund-edge-cases.md` · 公募边界表述版

```bash
--product public_fund --audience public --media online --institution fund_manager
```

**专门的误报测试样本**，全文由「表面像违规、实际合规」的表述构成，每句都刻意包含违禁词表中的字眼：

| 边界表述 | 为什么不是违规 |
|---|---|
| 「……也不表明投资于本基金没有风险」 | 证监会法定注册声明，监管强制要求 |
| 「其预期风险与预期收益高于债券型基金」 | 《运作管理办法》风险收益特征标准句式 |
| 「业绩比较基准收益率」 | 法定允许的基准列示方式 |
| 「不承诺保本」「并非保本型产品」「不得以任何方式暗示保本」 | 否定语境 |
| 「属于中低风险以上产品」 | 适当性管理标准分级表述，非「低风险」 |
| 「最低申购金额」「最长持有期」 | 客观业务参数，非绝对化用语 |
| 「客户资金由托管银行独立存管，账户安全」 | 账户安全提示，非产品安全性宣传 |
| 「可投资于保险资管产品」 | 资产类别名称，非保险保障暗示 |
| 「已完成备案，备案编码 SXXXXX」 | 客观陈述，未与安全性表述关联 |
| 「首次募集规模上限为 50 亿元」 | 客观列示，未强调时间紧迫 |
| 「限时费率优惠活动」 | 费率活动，非募集期饥饿营销 |

文中的 `<!-- 边界点：... -->` 注释说明每处的性质。引擎会跳过 HTML 注释（注释不会出现在最终发布物中，扫描它只产生噪音），因此注释内引用的违禁词不会被计入。

**期望 violation 为 0。** 这是规则库精确度的核心检验。

### 4. `sample-public-fund-video-script.md` · 短视频投放脚本

```bash
--product public_fund --audience public --media video --institution fund_manager
```

分镜脚本形式，验证**载体维度路由**。FMT-003（动态素材风险提示时长不足 5 秒）只在 `media` 为 video 或 audio 时适用，脚本中「风险提示停留 3 秒」会触发该规则。

**重点观察**：Agent 是否识别出这是视频材料并传入 `--media video`。若传成 online，FMT-003 不会被应用。

### 5. `sample-private-fund-violating.md` · 私募违规版

```bash
--product private_fund --audience specific --institution fund_manager
```

验证**公私募分路由**，这是规则库的核心设计。触发的规则中有 5 条是公募场景下完全不适用的：

- BAN-002 承诺保本保收益（私募）——依据《私募投资基金监督管理条例》第二十条，行政法规位阶
- BAN-004 结构化增信安排（差额补足、流动性支持承诺函、劣后级覆盖优先级）
- BAN-011 利用备案或托管安排增信
- PERF-010 私募证券基金业绩展示门槛
- PERF-011 私募不得节选少于 6 个月的过往业绩

**重点观察**：材料中的「避险」一词。该词在私募场景明文禁用（中基协《私募募集办法》第二十四条第四项），在公募场景无现行条款依据（出自已废止的证监会公告〔2008〕2 号）。如果报告把它按公募条款引用，就是路由错误。

### 6. `sample-private-fund-compliant.md` · 私募合规版

```bash
--product private_fund --audience specific --institution fund_manager
```

私募场景的误报基线，**期望 violation 为 0**。含合格投资者认定、完整风险揭示、规范的业绩展示与数据来源标注。

### 7. `sample-securities-firm-promo.md` · 券商推广材料

```bash
--product public_fund --audience public --media online --institution securities_firm
```

验证**机构类型维度路由**。REQ-005（券商推广材料未标明必备三项：推广材料标识、风险提示、适合对象）仅在机构类型为证券公司时适用，依据中证协《证券公司投资者适当性制度指引》第二十二条。

材料中还含客户证言（「在华穗买基金三年了……收益比银行理财强多了」），属绝对禁止的推荐性文字。

### 8. `sample-wealth-mgmt-violating.md` · 理财产品违规版

```bash
--product wealth_mgmt --audience public --media online --institution wealth_subsidiary
```

验证**理财产品专属规则**。理财不适用《基金宣传推介暂行规定》，其规则依据是《理财公司理财产品销售管理暂行办法》与《广告法》：

- REQ-007 未标明风险等级——《理财销售办法》第三十条，这是国内唯一一处法规级、明文要求在宣传材料上标注风险等级的依据
- PERF-014 突出展示业绩比较基准数值且未说明测算依据——《理财销售办法》第二十五条第三项
- BAN-013 保本保收益或无风险暗示——《广告法》第二十五条第（一）项，含「从未发生过本金损失」这类历史兑付话术
- REQ-011 缺少风险提示——《广告法》第二十五条第一款

只有 7 条规则适用，是四类产品中最少的。这反映规则库当前对理财产品的覆盖仍偏薄。

## 三、在 WorkBuddy 中测试

把样本文件拖入对话，说「帮我审查一下这份材料能不能发」。

四个判断标准：

1. **是否主动确认上下文**。Agent 应当询问或明确说明产品类型、受众范围、材料载体、机构类型，而不是自行猜测。`SKILL.md` 规定这四个维度不许猜。

2. **数字是否与基线一致**。对照第一节的表格。不一致说明没有真正调用扫描脚本。

3. **是否每项都带法条原文**。应包含法规全称、条款号、条款原文，且原文须与 `references/legal-index.md` **逐字一致**——不得删减主语、不得把「应当」简写为「应」、不得替换标点。这是本工具与通用文案检查工具的根本差异，合规人员要据此举证。

4. **是否做了语义研判**。规则引擎覆盖不到的问题应由 Agent 补充，例如公募违规版中的「穿越牛熊」（不含违禁词但以叙事方式暗示确定收益）、把混合型基金描述为「低风险」（风险定性与产品实际特征矛盾）、通篇只讲收益不讲风险的整体印象误导。

## 四、已知未覆盖

4 条规则未被任何整份样本触发，但均有内嵌测试用例覆盖：

| 规则 | 说明 |
|---|---|
| BAN-001 | 公募保本保收益。现有公募违规样本使用的是「安全性有保障」这类间接表述，未出现直接的「保本」字样 |
| FMT-005 | 已废止规则中的禁用词（净值归一、首只、最大、最好、最强） |
| PERF-003 | 业绩展示须覆盖完整会计年度 |
| REQ-009 | 特殊基金品种专门揭示（养老目标、货币市场基金、QDII、REITs 等） |

## 五、维护说明

修改规则后，重新执行以下命令确认基线未被破坏：

```bash
python3 scripts/validate_rules.py    # 129 个内嵌测试须全部通过
```

三条合规样本（公募合规版、公募边界表述版、私募合规版）的 violation 数**必须始终为 0**。任何一条变成非 0，都说明新改动引入了误报，须回退或修正。
